# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Notes for Claude Code sessions on this repo. Keep it short — the README covers user-facing usage.

## Layout

- `fuzzyclock_core.py` — single source of truth for time phrasing (`fuzzy_time`, `DIALECTS`), font loading (`load_font`, `FONT_VARIANTS`, `pick_random_font`), the clock-face drawing (`render_clock`, `draw_border`, `FRAME_VARIANTS`, `FONT_FRAME_CATEGORY`/`frame_for_font`), and the NOAA sunrise/sunset approximation (`sun_times`). Both entry points import from it; do not reintroduce duplicate copies.
- `fuzzyclock_daemon.py` — long-running daemon, invoked by systemd. Handles the day/after_hours/night state machine, partial refresh, GPIO button, render-failure recovery, and graceful SIGTERM/SIGINT.
- `fuzzyClock2.py` — dev/dry-run script. `--dry-run` renders to PNG and works on any Linux/macOS box; `--dialect` picks a phrasing; `--font` and `--frame` override the font variant and border style (`--font random` rolls one vendored variant for the single render); `--time HH:MM` pins the clock to a fixed time for previews.
- `fuzzyclock_config.yaml` — single source of daemon config: `dialect`, `font`, `frame`, `latitude`, `longitude`. Loaded once in `main()` by `_load_config()`. Missing/malformed file → all defaults and after-hours disabled (daemon stays on plain day/night). Unknown dialect/font/frame logs a warning and falls back; missing, non-numeric, NaN/inf, or out-of-range coords log a warning and disable after-hours but keep the resolved dialect/font/frame.
- `fonts/` — vendored OFL/Apache TTFs/OTFs for every non-system font variant. `vendored_font_variants()` filters `FONT_VARIANTS` to keys with at least one file actually on disk under this directory, so the random-font mode never rolls a variant that would `SystemExit` in `load_font()`.
- `docs/fonts.md` + `docs/preview-*.png` — catalog of every registered font variant with rendered previews. Regenerated by hand when fonts are added; keep the comment block at the top of `fuzzyclock_config.yaml` in step with the list there.
- `systemd/fuzzyclock.service` — templated unit. `__REPO_DIR__` and `__USER__` are sed-substituted by `deploy.sh`.
- `waveshare_epd/` — vendored driver. Don't edit unless syncing upstream from Waveshare; ruff is configured to skip it (`extend-exclude` in `pyproject.toml`).

## Tests & lint

- Run everything: `python3 -m unittest discover`. Single file: `python3 -m unittest test_fuzzy_time` (or `-v` for verbose). Single test: `python3 -m unittest test_daemon.CurrentModeTests.test_polar_midnight_sun_falls_back_to_day`.
- Lint: `ruff check .` (CI runs this; config is in `pyproject.toml`, `target-version = "py39"` — don't bump it without checking that UP017 doesn't rewrite `timezone.utc` → `UTC`, which breaks 3.9/3.10).
- Format: `ruff format .` is enforced via `ruff format --check .` in CI. Run it locally before pushing if you've touched any non-vendored Python.
- PIL is needed (transitively via `fuzzyclock_core`); install with `pip install Pillow` or apt's `python3-pil`. DejaVu fonts must be present too (`fonts-dejavu-core`) or `load_font()` will exit.
- `test_fuzzy_time.py` — pure-logic cases for `fuzzy_time()`, including dialect tables. Add cases here when touching the phrasing logic.
- `test_render.py` — smoke tests for `draw_border`, `render_clock`, the auto-sized body font (`FitBodyFontTests`, `RenderClockOverflowTests`), every `FRAME_VARIANTS` style, and the random-font shuffle bag (`RandomFontShuffleBagTests`). Asserts ink-on-canvas, not pixel-exact output, to stay font-version stable.
- `test_sun.py` — pins the `sun_times` NOAA approximation against published sunrise/sunset values (tolerance ±5 min) and the polar-night / midnight-sun branches.
- `test_daemon.py` — covers `current_mode`, `_sleep_to_next_tick`, `_load_config` (YAML parsing + dialect/font/frame/coordinate validation), `_resolve_font`/`_resolve_frame`, the cross-thread render-retry counter, the button listener + supervisor, `reset_base_image`, `display_goodnight`/`draw_clock` with fake EPDs, `_call_with_timeout`/`_epd_init` (`CallWithTimeoutTests`, `EPDInitTests`, `BusyPinTimeoutTests`), and the `main()` loop driven by a stubbed wall clock. Imports `fuzzyclock_daemon` directly; the module's hardware imports are guarded so this works on CI without GPIO/EPD. `BusyPinTimeoutTests` swaps in a throwaway lock per test — its simulated stuck calls never return, so the abandoned worker would otherwise hold the real module-level `epd_lock` for the rest of the run and wedge every later test. Do the same for any new test that simulates a hung driver call.
- `test_daemon_import.py` — bare `import fuzzyclock_daemon` smoke test. Catches eager hardware calls at module scope that would crash on CI before the unit tests get a chance to run.
- `test_dry_run.py` — invokes `fuzzyClock2.py --dry-run` as a subprocess and validates the PNG, plus `DrawFuzzyClockInProcessTests` that calls `draw_fuzzy_clock()` directly to exercise the in-process code path without the subprocess overhead. Also exercises the EPD-not-available fallback.
- Manual render check: `python3 fuzzyClock2.py --dry-run --output /tmp/out.png`.
- CI: `.github/workflows/test.yml` runs ruff plus the full suite on Python 3.11 and 3.12 on every push and PR.

## Deploy path

- `deploy.sh` installs Python deps via `apt` (`python3-pil`, `python3-gpiozero`, …), **not** pip. Bookworm's PEP 668 blocks pip against the system Python. `requirements.txt` is for off-Pi dev environments only.
- `deploy.sh` is idempotent: re-running re-renders the unit file (atomic `install` to a temp path) and `systemctl restart`s the service, so it picks up edits to `fuzzyclock.service` or pulled-in code. It re-execs under sudo if not root, and on failure dumps `journalctl -n 50` + `systemctl status` to stderr and exits non-zero.
- The systemd service file uses `__REPO_DIR__` and `__USER__` sentinels; `deploy.sh` substitutes them via `sed` using the invoking user (`${SUDO_USER:-$USER}`) and the repo's actual location. Don't hardcode `/home/pi` or `User=pi` back in.
- There is intentionally no `.timer` file — the unit has `Restart=always` (`RestartSec=10`, `StartLimitBurst=5`/`StartLimitIntervalSec=300`) and the daemon handles day/night internally.

## Daemon architecture

- **Mode state machine.** `current_mode(now, lat, lon, after_hours_enabled, day_start=DAY_START_HOUR, day_end=DAY_END_HOUR)` returns `"day"`, `"after_hours"`, or `"night"`. Outside the wake window (`DAY_START_HOUR..DAY_END_HOUR`, currently 7..23) it's always night. Inside the window, the sun decides between day and after_hours; with no coordinates (or polar night/midnight sun) it falls back to plain day. Keep this function pure — `_current_mode_now()` is the wrapper that reads module globals; the `day_start`/`day_end` kwargs exist for tests, don't wire them to module globals.
- **Tick cadence.** Main loop wakes every `TICK_INTERVAL` (60 s) for mode-transition latency, but only re-renders on a mode change or on a 5-minute wall-clock boundary (`UPDATE_INTERVAL=300`). `_sleep_to_next_tick` aligns sleeps with wall-clock multiples to eliminate cumulative drift; its result is always in `(0, interval]` (never zero — that would busy-loop).
- **Partial-refresh base image.** `epd.displayPartial` diffs against the last `displayPartBaseImage`. Any full `epd.display()` (e.g. goodnight) and any normal/inverted swap leaves the base stale, so call `reset_base_image(epd, invert=…, frame=…)` on every mode transition. The `_sun_times_cached` LRU keeps the ephemeris stable for the day. `_last_applied_frame` tracks which border style was painted onto the current base — `draw_clock` reseeds the base mid-render whenever it changes (only relevant in random-font + auto-frame mode, where the resolved frame can shift between ticks).
- **Render lock.** `_render_lock` (an `RLock`) wraps the whole `draw_clock` body and `reset_base_image` so the main loop and the button thread can't interleave a `_last_applied_frame` check with another thread's reseed. Reentrant because `draw_clock` calls `reset_base_image` from inside the locked region. `epd_lock` is the separate, finer-grained guard around individual SPI writes — but it is acquired and released by `_call_with_timeout`, not by the call sites (see **Bounded EPD calls** below), so don't take it directly.
- **Render-failure recovery.** Failures from both the main loop and the button thread feed a shared counter (`_render_state_lock`). After `RENDER_RETRY_REINIT` (3) consecutive failures, the next render path re-inits the EPD and reseeds the base image. After `RENDER_RETRY_FATAL` (10), the daemon exits and lets systemd restart it. `_on_render_success()` clears both flags. If you add a new render path, call both helpers.
- **Bounded EPD calls.** The vendored driver's `ReadBusy()` polls the BUSY pin in a plain `while` loop with no timeout of its own, and every *rendering* driver call (`init` / `display` / `displayPartial` / `displayPartBaseImage`) goes through it at least once — so a stuck pin would hang the daemon forever with the render-failure counter none the wiser. `sleep()` is the exception: it sends DEEP_SLEEP, waits a fixed 2s and calls `module_exit()` without ever reading BUSY, so its timeout guards a wedged SPI write rather than a stuck pin. It is wrapped anyway, for that reason and to keep one call convention. `_call_with_timeout(func, *args, timeout=EPD_CALL_TIMEOUT_SEC, lock=...)` runs each call on a daemon worker thread and bounds how long the caller waits, raising `EPDTimeoutError` (a `RuntimeError` subclass, so the existing `except Exception` handlers in `draw_clock` / `reset_base_image` / `main()` already catch it). Most of those sites feed the render-failure counter, but **not all of them do**: the night-transition handlers around `display_goodnight()` and the overnight `epd.sleep()` only log, deliberately, so a stuck panel at bedtime can't burn through `StartLimitBurst` and disable the unit overnight. A timeout there is recorded in the journal and retried in the morning, not counted toward re-init or the fatal threshold. A worker thread, not `SIGALRM`: signals only interrupt the main thread, and both the main loop and the button thread call into the driver. **The lock is owned by the helper, not the call site** — `_call_with_timeout` acquires `epd_lock` (also bounded by `timeout`) *before* starting the worker and the worker releases it when the call actually returns. Python can't kill a thread, so a timed-out call is abandoned still running against the bus; holding the lock until it genuinely finishes is what stops a subsequent call (notably the recovery path's re-init) from talking to SPI/GPIO concurrently with it and corrupting panel state. The subsequent call instead blocks on acquisition, gets its own `EPDTimeoutError`, and feeds the counter — so enough consecutive timeouts reach `RENDER_RETRY_FATAL` and exit the process, which is the only way to actually shed a permanently wedged worker.
- **`epd.init()`'s `-1` must be checked.** The vendored `init()` returns `-1` when `epdconfig.module_init()` fails and otherwise carries on as if nothing were wrong, so a bare call site silently proceeds against an unconfigured panel. Go through `_epd_init(epd)` (timeout- and lock-guarded) and check the result at every call site — the startup init and both re-init paths in `main()` (the overnight-sleep wake and the render-failure recovery) do.
- **Button thread supervision.** The button listener runs under `_button_supervisor`, which catches exceptions and restarts the listener after a 10s backoff. Without it, a silent crash in the button thread would leave the daemon running with no button input — and since the main process is still alive, systemd wouldn't restart it. The supervisor exits cleanly when `_stop_event` is set.
- **Overnight panel sleep.** Entering night mode deep-sleeps the controller (`epd.sleep()`) right after a *successful* goodnight slide — the e-ink image persists without power, and the panel shouldn't be driven for hours with no refresh. `main()` tracks this in a local `panel_asleep` flag: the wake transition re-inits before reseeding the base, the recovery path's `epd.init()` also clears it, and the post-loop cleanup skips its own `epd.sleep()` when the overnight sleep already ran (sleep tears down the SPI handle, so a second call raises). Short button presses are ignored in night mode for the same reason — and because the main loop never repaints goodnight while the mode stays "night", a stray render would freeze a stale clock face until morning. Long press (shutdown) still works at night.
- **Button shutdown needs sudo.** The unit runs the daemon as a regular user, so `shutdown_procedure` calls `sudo -n shutdown -h now` and logs an error on nonzero exit. `deploy.sh` installs the matching NOPASSWD rule at `/etc/sudoers.d/fuzzyclock` (visudo-validated before install). Don't switch it back to a bare `shutdown` — polkit denies that to a non-root daemon.
- **Config loading.** `_load_config(path=CONFIG_PATH)` parses `fuzzyclock_config.yaml` with `yaml.safe_load` and returns `(dialect, font, frame, latitude, longitude)`. Unknown dialect/font/frame logs a warning and falls back to the default; coords that are missing, non-numeric, non-finite (`math.isfinite` rejects NaN/inf), or outside `[-90, 90]` / `[-180, 180]` log a warning and become `(None, None)` so after-hours stays off. The two checks earn their place for different reasons. **Finiteness** prevents a crash: NaN or inf reaches `sun_times()` and raises `ValueError` on *every* startup, bricking the appliance into a systemd restart loop rather than degrading to plain day/night. **Range** is about correctness, not crashes — `sun_times()` is happy to accept a longitude of 181 and return plausible-looking times, and an out-of-range latitude quietly takes the polar `(None, None)` fallback, so without the bounds a typo silently yields the wrong sunrise or no after-hours at all, with nothing in the log to say why. Called once from `main()` (not at import time) so tests can import the module without filesystem reads or warnings.
- **Font and frame variants.** Stored in module globals `FONT_VARIANT` and `FRAME_VARIANT` after `_load_config()` returns. `_init_fonts()` only pre-loads the goodnight font now — `render_clock` auto-sizes its body fonts at render time via `_fit_body_font`, so there's no fixed body/tiny/hour pair to seed. `_resolve_frame(font_variant)` maps `FRAME_VARIANT` to a concrete frame name: when `FRAME_VARIANT == AUTO_FRAME` it looks up the font in `FONT_FRAME_CATEGORY`; otherwise it returns `FRAME_VARIANT` directly. Most vendored variants check `<repo>/fonts/*.ttf` before any apt path, letting users drop a custom TTF without an apt install.
- **Random-font mode.** `font: random` in config flips `FONT_VARIANT` to the `RANDOM_FONT` sentinel. `pick_random_font()` in `fuzzyclock_core` runs a *shuffle bag*: it deals each eligible vendored variant once before reshuffling, so the user sees every font before any repeats (music-shuffle, not uniform i.i.d.). Across bag boundaries the next pick is swapped deeper if it would repeat the previous one. The eligible set is `vendored_font_variants()` — variants with at least one file present in `fonts/`. The daemon's `_resolve_font(phrase)` re-rolls only when the rendered phrase changes (so a button press inside the same 5-minute bucket keeps the variant), and **the first render after `_init_fonts()` reuses the init-time seed** (`_last_phrase is None` sentinel) instead of popping another bag slot — otherwise the goodnight preload would silently consume a slot the user never sees on the clock face, breaking the "every variant before repeats" guarantee at startup. In random + auto-frame mode the frame can change between renders; `draw_clock` calls `reset_base_image` mid-body when `frame != _last_applied_frame` to keep partial refresh diff-clean.

## Gotchas

- Fonts: `fuzzyclock_core.load_font()` tries vendored `fonts/` first, then apt paths, then macOS fallbacks. It raises `SystemExit` if no candidate is found, so it must not run at module scope — `fuzzyclock_daemon._init_fonts()` is called from `main()` to populate `font_goodnight` (and seed the random-font pick), and `fuzzyClock2.draw_fuzzy_clock()` defers to `render_clock`'s own auto-sizing. `render_clock` itself calls `load_font(size, variant=...)` at each candidate size via `_fit_body_font`, so a missing font surfaces at render time, not import time. `draw_clock`/`display_goodnight` call `_require_fonts()` first — PIL silently falls back to a default bitmap font when handed `None`, which would mask a missed `_init_fonts()` with a subtly-wrong render.
- The goodnight slide is a *themed* render now: black canvas, white rustic frame, auto-sized "Goodnight" hard-coded to the `unifraktur-maguntia` variant regardless of `FONT_VARIANT`. The blackletter pairing is intentional — keep `display_goodnight` calling `load_font(size, variant="unifraktur-maguntia")` for the headline and `draw_border(..., frame="rustic")` for the border, not the active config.
- Body text is auto-sized per render. `_fit_body_font` walks `_BODY_MAX_SIZE` → `_BODY_MIN_SIZE` (40 → 14 pt) and returns the largest size where both lines fit within `width - 2*_CONTENT_PAD` and the two-line block clears the footer; `_CONTENT_PAD` (= 14) is the exclusion strip on all four sides matching every frame's outermost ink. The phrase + hour block is centred *between `_CONTENT_PAD` and the footer ink top* in ink coordinates (not bbox coordinates) so fonts with large top-bearing (Pacifico, Charis SIL, blackletters) don't visually drift up. If you change any of the layout constants, run `test_render.RenderClockOverflowTests` — it locks in the exclusion zone with a `_RecordingDraw` fake.
- E-ink display is mounted upside down; all writes are `.rotate(180)`'d just before `epd.display*()`. Keep that at the SPI boundary, not inside `render_clock`.
- `epd_lock` guards every SPI write in the daemon; `_render_lock` (reentrant) wraps the whole render body so the frame-check + base-reseed sequence is atomic across threads. If you add a new path that talks to `epd`, route it through `_call_with_timeout(..., lock=epd_lock)` rather than acquiring `epd_lock` yourself; if it also does a check-then-reseed on `_last_applied_frame`, wrap it in `_render_lock` too. The signal handler does no I/O and acquires no locks — it just sets `_stop_event` so the main loop can exit cleanly without deadlocking against an in-flight render.
- `fuzzy_time()` caps the 5-minute bucket at 11 on purpose — minutes 57–59 must read "almost [next hour]", not wrap back to "just after [current hour]". There's a test for this in every dialect; don't "simplify" the `min(..., 11)`.
- Dialect `hour_advance_at` must stay in `1..11`. There's a module-load-time guard in `fuzzyclock_core.py` (`_validate_dialects`) that raises `ValueError` if a dialect violates this — it'd silently break the "almost [next hour]" invariant via `% 12`. If you add a new dialect that needs an early advance (like German's `5`), keep it within the range.
- Hardware imports (`gpiozero`, `waveshare_epd`) catch both `ImportError` *and* `RuntimeError` — gpiozero raises `RuntimeError` on non-Pi Linux when it can't find a GPIO backend. Don't narrow the except clause.
- Daemon module-level state (`DIALECT`, `FONT_VARIANT`, `FRAME_VARIANT`, `LATITUDE`, `LONGITUDE`, `AFTER_HOURS_ENABLED`, `font_goodnight`, `_current_random_font`, `_last_phrase`, `_last_applied_frame`) is populated in `main()` or first render, not at import time, so `import fuzzyclock_daemon` in tests doesn't trigger filesystem reads, warning logs, or a SystemExit on a font-less host. Keep it that way — `test_daemon_import.py` exists specifically to catch regressions.
- When a font has multiple vendored candidate paths (e.g. `pigeonette` accepts Bold/Regular/plain), `vendored_font_variants()` considers all of them via `any(os.path.exists(...))`, not just the first. The random-font mode relies on this — filtering only the preferred filename would silently exclude variants whose top choice happens to be missing on a given install.
- Adding a new font variant takes four touches: register the candidate list in `FONT_VARIANTS`, map it in `FONT_FRAME_CATEGORY` so auto-frame picks something sensible (unmapped → bauhaus via `frame_for_font`'s default), mention it in the `fuzzyclock_config.yaml` comment block, and (by convention) regenerate `docs/preview-<name>.png` + add a row to `docs/fonts.md`. If the vendored file is also dropped into `fonts/` then random-font mode picks it up automatically.
